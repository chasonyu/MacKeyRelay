# 事件路径与设计边界

```text
物理键盘 / Karabiner 虚拟键盘
    ↓
公开 CGEventTap（HID 位置、头部插入）
    ├─ 非目标窗口 → 原事件继续本机处理
    └─ 目标窗口 → 跟踪按键所有权 → 复制事件、标记来源
                                      ↓
                           CGEventPostToPid(Screen Sharing)
                                      ↓
                  苹果 SSApplication / 原生网络传输 → 远端 Mac
```

`postToPid` 的成功调用只表示投递请求已发出，不是远端收到或执行的确认。

普通键与修饰键分开处理。复制原始 `flagsChanged` 保留左右设备级位；若开始捕获时已有物理修饰键按住，在普通键之前补一次修饰键状态同步。普通按键不会每次启动独立 shell 进程。

前台/键盘焦点、事件投递和远端执行不构成原子操作。工具会管理捕获状态并尽力清理，但不承诺切换瞬间绝对无竞态。尤其当苹果已撤销活动 consumer 时，后台 flagsChanged 的释放可能无效；应通过交互验收确认原生的焦点清理是否足够。

当前不修改 Karabiner。若公开 event tap 无法阻止特定上游全局热键，再根据实测选择 Karabiner 专用规则或其他捕获通道；不预先承诺所有热键软件均可被拦截。

只用主线程的 CFRunLoop 串行处理状态；SIGINT/SIGTERM 只设置原子停止标志，由定时器清理退出。程序不记录键盘文本，不联网，不读取剪贴板，不在远端执行代码。
